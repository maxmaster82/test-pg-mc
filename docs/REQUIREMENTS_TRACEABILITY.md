## Assumptions

| ID  | Assumption                                                                                                                                                                | Why it is safe / how to reverse                                    |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| A1  | "Dashboard with search, filtering, sorting, pagination" means the admin portal: each entity list provides these features; an Overview page gives counts and entry points. | Covers both readings; a single combined screen would be worse UX.  |
| A2  | One role (administrator); no RBAC.                                                                                                                                        | Not required; RBAC listed only as a bonus.                         |
| A3  | Mock auth: one seeded demo admin; opaque token in `localStorage`.                                                                                                         | Documented trade-off; cookie-based session is the production path. |
| A4  | Ticket `quantity` = available inventory; `status ∈ draft, on_sale, paused, sold_out`; `sold_out` is set manually, not derived.                                            | Simple and explicit; derivation is a backend rule to add later.    |
| A5  | Currencies: EUR, USD, GBP, CHF. Price stored as integer minor units; 0 allowed (free tickets).                                                                            | Avoids float errors; list extendable.                              |
| A6  | Event `status ∈ draft, published, cancelled, completed`; country is ISO 3166-1 alpha-2; dates are ISO date-times entered in local time; end ≥ start.                      | Standard formats; `Intl` displays names.                           |
| A7  | Category names unique (case-insensitive); description optional ≤ 500.                                                                                                     | Prevents ambiguous selects.                                        |
| A8  | Deleting an event/category with tickets is refused (409); no cascade.                                                                                                     | Non-destructive default; soft delete is the future direction.      |
| A9  | Records carry a `version` for optimistic concurrency (409 on stale update).                                                                                               | Demonstrates multi-admin safety at low cost.                       |
| A10 | Mock data persists in `localStorage` in the browser with a "Reset demo data" action; tests use a fresh db.                                                                | Makes demos realistic across reloads.                              |
| A11 | MSW runs in the Docker production build because there is no backend (`VITE_API_MOCKING=true` by default).                                                                 | Flag-controlled; real deployments disable it.                      |
| A12 | English-only UI; formatting uses the browser locale via `Intl`.                                                                                                           | i18n not required.                                                 |
| A13 | Latest evergreen browsers only (Chrome, Firefox, Safari, Edge).                                                                                                           | Admin tool; no legacy support required.                            |
| A14 | The assessment PDF is not committed; the repository will be public.                                                                                                       | Third-party document.                                              |
| A15 | Publishing the public repository is done by the developer, not the agent.                                                                                                 | Explicit instruction.                                              |
